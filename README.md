60wattslides


A website that begins finished, then becomes unmistakably yours.

60wattslides is the slide-first website platform created by 

60 Watts of Clarity, an AI education company founded by Jason Fernandez, MA, LMSW. Rather than starting with a blank page builder, each customer receives a visual, full-screen website with a guided story already in place. They use a focused CMS to replace the words, images, video, colors, calls to action, and interactions until the website reflects their own work.

The idea follows the 60 Watts of Clarity philosophy: people do not need overwhelming technology to move forward. They need enough light, structure, and practical control to see the next step clearly.

What this project is

This repository contains both sides of the product:

•
A responsive, public slide website that visitors explore as a visual story—not as a conventional scrolling page.

•
A focused CMS that edits the same live renderer visitors see.

•
A reusable Media Library for photos, video, and privacy-enhanced YouTube embeds.

•
A lightweight, slide-connected CRM for workshop requests and tailored-path enquiries.

•
A source-bound slide search: it finds answers only in published slide content rather than inventing a generic AI response.

•
A PostgreSQL-backed multi-customer path for signed-in customers, publishing, subscriptions, CRM records, media metadata, and domain requests.

Why a slide website?

A slide website is not a PowerPoint file placed on the web. It is a website with a different interaction model:

•
Visitors move through full-viewport story moments with keyboard, swipe, and previous/next controls.

•
Photography, video, typography, navigation, and search live inside one coherent visual composition.

•
Customers start with a complete starter site instead of guessing which page sections to make.

•
The CMS changes live content and design settings; it does not flatten the website into screenshots.

•
The public layouts avoid generic raised content cards. Programs, sessions, questions, and interactive moments use the project’s editorial Light Path language: connected waypoints, ruled ledgers, margin notes, and light nodes.

Core product capabilities

1. A premade website customers can make their own

The starter deck opens with seven editable website slides and can grow from there. Customers can select a slide visually, use the live preview, and change:

•
Headline, supporting copy, section labels, story beats, and visitor-facing language.

•
Typeface, font size, weight, alignment, colors, accent lines, backgrounds, and layout settings.

•
Photos, video, photo focal point, accessible descriptions, YouTube embeds, and reusable library assets.

•
One or more CTA buttons, including internal slide navigation, the built-in search bar, email, phone (tel:), secure web links, and map links.

•
Slide order, visibility, progress treatment, navigation controls, and auto-advance behavior.

New slides begin hidden so unfinished work does not appear on the published website.

3. CMS built around one task at a time

The CMS uses four clear workspaces:

Workspace
What it is for
Slides
Select a thumbnail, view the finished website slide, then edit one focused section at a time: Text, Media, or Buttons.
Media Library
Upload and reuse photos and video, register YouTube media, search assets, see which slides use an asset, and assign it to the current slide.
CRM
Review workshop requests and tailored-path enquiries, add private notes, update a contact’s stage, export local contacts as CSV, and jump back to the source slide.
Site Settings
Manage branding, logo, navigation and search language, slideshow behavior, and domain-connection intent.




The Slides workspace follows a calm publishing-tool pattern: visual thumbnail rail on the left, selected website slide in the center, and a narrow contextual editor on the right. On phones, the interface stacks in a deliberate order without hiding core authoring controls.

4. Search grounded in published slides

The search bar is intentionally not a generic chatbot. It searches the published website’s own slide content.

•
A supported question moves the visitor to the relevant slide and shows the matching source text.

•
Date, location, and price questions require that specific information to exist in the quoted source.

•
Ambiguous matches offer choices.

•
If the website does not contain the answer, the visitor receives a clearly marked temporary, unverified topic slide—not an invented answer.

•
An owner who is browsing their own website in the same browser can choose to bring that unanswered topic into the CMS as a hidden draft.

5. CRM and workshop requests

Workshop and tailored-path slides connect directly to the CMS CRM. The CRM records the source slide, visitor choice, request type, contact details, current stage, and private notes.

A workshop request is not a seat confirmation or payment. Seat capacity is applied only when the owner marks a booking as confirmed. This prevents unverified requests from consuming availability.
